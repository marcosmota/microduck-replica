## Estrutura de montagem

```
Corpo do tronco 199g
├─ Quadril esq. yaw→roll 23g → quadril esq. roll 6g → coxa esq. 48g → canela esq. 22g → tornozelo+pé esq. 30g
├─ Base do pescoço 37g → peça de pitch do pescoço 6g → mecanismo yaw/roll da cabeça 49g → conjunto da cabeça+bico 189g
└─ Quadril dir. yaw→roll 23g → quadril dir. roll 6g → coxa dir. 48g → canela dir. 22g → tornozelo+pé dir. 30g

Robô completo 737.2g   Dimensões externas 144 × 141 × 264 mm
```

O tronco e a cabeça pesam quase o mesmo (199g vs 189g): **a cabeça responde por um quarto do robô completo, e o centro de massa é muito alto**,
o que explica por que a política de marcha dele é difícil de treinar.

## Parâmetros das juntas

Cada perna tem 5 graus de liberdade, e cabeça e pescoço têm 4: **14 controlados**.
O robô completo na prática leva **15 Dynamixel XL330**: o 15º aciona o bico/mandíbula por uma ligação passiva e não entra no espaço de ações.

| Junta | Curso |
|---|---|
| `hip_yaw` | -25° ~ +30° |
| `hip_roll` | ±22° |
| `hip_pitch` / `knee` / `ankle` / `head_pitch` | ±90° |
| `neck_pitch` | -90° ~ +60° |
| `head_yaw` | ±170° |
| `head_roll` | ±25° |

## Solução eletrônica inferida a partir do runtime

<div align="center">
  <img src="../assets/hw/01-物理布局.png" alt="Visão geral da parte eletrônica do Microduck: onde cada placa fica" width="880">
  <br>
  <sub><b>Disposição física dos cinco módulos</b>: a caixa tracejada cinza é a região física, a caixa de linha cheia é o módulo, e a caixa tracejada vermelha indica montagem <b>fora</b> da carcaça.<br>
  <b>Laranja</b> é o barramento dos servos (de cima para baixo), <b>vermelho</b> é a alimentação da bateria (de baixo para cima).<br>
  O ponto mais fácil de errar: <b>controlador, HAT e câmera estão todos na cabeça</b>, a câmera fica a cerca de 13 mm do centro da placa principal e sem junta entre elas,<br>
  então o flat MIPI não passa pelo pescoço; o que passa pelo pescoço são o barramento dos servos e os cabos de alimentação.<br>
  <a href="../docs/硬件入门.md">Conjunto completo de figuras e explicações →</a>　·　<a href="../assets/hw/Microduck硬件图集.pdf">Baixar o atlas em PDF (7 figuras, A3)</a></sub>
</div>


**Um barramento serial TTL de 1 Mbps resolve tudo.**

```
                Radxa Zero 3W (RK3566) · Armbian
                  ├── UART2  1 Mbps TTL fio único half-duplex ── 15× XL330 + imu_to_dxl (ID 200)
                  ├── I2C3   400 kHz (pin 3/5) ────── AIC3104@0x18 · ToF@0x29 · BMI088 (não usado)
                  ├── I2S3   12.288 MHz ───────────── áudio
                  ├── MIPI CSI ────────────────────── IMX219 (I2C@0x10, girado 90°)
                  ├── Bluetooth ───────────────────── gamepad / app de celular
                  ├── Wi-Fi ───────────────────────── WebRTC
                  └── USB-C ───────────────────────── alimentação + maskrom
```

| | |
|---|---|
| **Controlador principal** | **Radxa Zero 3W**: módulo comercial, **não uma placa-base customizada** |
| SoC | RK3566, quad-core Cortex-A55, Mali-G52, NPU de 0.8 TOPS. O oficial divulga 1 GB de memória / 32 GB de armazenamento; para a réplica, basta comprar a versão de 1G ou 2G **sem eMMC** + cartão microSD de 32 GB, usando só canais oficiais; veja [电控采购清单](../docs/电控采购清单.md#qual-configuração-comprar) |
| **Barramento dos servos** | **TTL half-duplex de fio único**: **não é** RS-232 e **também não é** RS-485. Dynamixel Protocol V2 @ 1 Mbps, em `/dev/ttyS2` |
| **Placa própria 1** | **`imu_to_dxl` v2**: um LSM6DSV16X que fala Dynamixel: ID de barramento 200, registrador 124, bloco de 12 bytes lido de volta no **mesmo** `sync_read` junto com os servos |
| **Placa própria 2** | **RPI Robot HAT**: TLV320AIC3104 @ 0x18, um BMI088 inativo, soquete Stemma para o ToF. **Já aberta oficialmente** ([`elec_RPI_Robot_HAT`](https://github.com/pollen-robotics/elec_RPI_Robot_HAT)) |
| Bateria | Sony NP-F550, lítio 2S. **Sem medidor de carga e sem ADC**: a tensão da bateria é obtida **lendo a tensão de alimentação que os próprios servos reportam** |
| Sensores | IMU LSM6DSV16X · ToF 8×8 VL53L5CX/L8CX · IMX219 (Raspberry Pi Camera v2) |

A `imu_to_dxl` é a jogada mais elegante de todo o projeto: **a IMU não usa I²C**, e sim se disfarça de escravo Dynamixel,
de modo que os dados de atitude voltam na mesma transação de barramento que o estado das juntas: não é preciso um segundo barramento, e o host também não precisa rodar fusão de atitude
(o bloco SFLP integrado ao LSM6DSV16X emite diretamente o quaternion de game rotation e ainda estima sozinho o bias do giroscópio).

**Detalhes completos:** [硬件方案逆向](../docs/硬件方案逆向.md) · [硬件规格速查](../docs/硬件规格速查.md)

## Viabilidade: dá para construir?

**O robô completo pode ser replicado; o gargalo está no custo, não na técnica.** Situação atual:

| Item | Estado |
|---|---|
| Geometria das peças | ✅ 47 STLs |
| Relações de montagem | ✅ Precisão de 0.1mm, desenhos prontos |
| Eixos / curso das juntas | ✅ Todas as 14 |
| Massa / inércia | ✅ Todos os 15 corpos rígidos |
| Modelo do servo | ✅ Dynamixel XL330 ×15 → [docs/执行器选型.md](../docs/执行器选型.md) |
| Rolamentos | ✅ Ø22×16×4 e Ø15×10×3 |
| **Placa HAT** | ✅ **KiCad + Gerber + BOM oficiais já abertos**, fabricar diretamente → [`elec_RPI_Robot_HAT`](https://github.com/pollen-robotics/elec_RPI_Robot_HAT) |
| **Placa `imu_to_dxl`** | ⚠️ Não aberta, precisa ser desenhada; o protocolo e o layout de registradores foram totalmente reconstruídos → [docs/硬件方案逆向.md](../docs/硬件方案逆向.md) |
| Controlador principal | ✅ **Radxa Zero 3W, módulo comercial** (antes se julgava, por engano, que era uma placa-base customizada) |
| **Lista de fixadores** | ✅ Já inferida a partir dos furos dos STLs → [docs/紧固件反推.md](../docs/紧固件反推.md) |
| Bateria / sensores | ✅ **NP-F550** 2S, IMX219, VL53L8CX, LSM6DSV16X |
| **Solução de roteamento de cabos** | ❌ Nenhuma |
| **Software de controle** | ✅ Com o mesmo Radxa Zero 3W como controlador, roda diretamente (Apache-2.0); só é preciso portar ao trocar o controlador |
| **ONNX de política oficiais** | ✅ Com o mesmo hardware podem ser usados diretamente (9); só é preciso retreinar ao alterar o corpo ou a parte eletrônica |

⚠️ **STL de simulação ≠ peça de engenharia imprimível.** A simulação só se importa com a forma externa e a inércia, sem garantir tolerâncias de encaixe,
furos roscados, sedes para insertos heat-set e espaço para cabos. Imprimir diretamente tem grande chance de não montar, sendo preciso complementar por conta própria os detalhes de engenharia.

💰 **Construir por conta própria provavelmente sai mais caro do que comprar, mas a diferença depende totalmente do canal.** 15 XL330 custam cerca de **$359** no site internacional da ROBOTIS,
**$412** no site dos EUA e **€603–629** com impostos na Europa, ou seja, tanto pode ficar "um pouco abaixo do preço de venda do robô completo" quanto "muito acima".
Somando controlador, bateria, fabricação das duas placas e filamento de impressão, fica necessariamente mais caro. O levantamento completo de preços está em [BOM.md](../BOM.md).

## Caminho realista

Abrir mão da réplica 100% (a placa `imu_to_dxl` e o CAD mecânico editável não foram abertos) e adotar **mecânica copiada + eletrônica construída por conta própria**:

| | Solução |
|---|---|
| Mecânica | Escolher no [repositório de CAD](https://github.com/fanhao375/microduck-replica-cad) o modelo e as instruções de montagem da versão de servo correspondente |
| Servos | XL330 × 15, peças comerciais, é só comprar |
| Controlador | **Radxa Zero 3W**, módulo comercial, o mesmo do oficial |
| Placa de IMU | Desenhar a `imu_to_dxl` você mesmo: LSM6DSV16X + MCU + transceptor half-duplex, o protocolo já foi reconstruído |
| Placa HAT | **Fabricar diretamente a partir dos Gerber oficiais** (4 camadas). Se não precisar de gravação, pode omitir a placa inteira, mas **o circuito de direção half-duplex exige uma placa adaptadora à parte**; veja [电控采购清单](../docs/电控采购清单.md#6-duas-pcbs) |
| Software | Com o mesmo controlador, o runtime Rust oficial roda diretamente (Apache-2.0) |
| Política | Os 9 ONNX oficiais podem ser usados; depois de alterar o hardware, retreine com [microduck_rl](https://github.com/pollen-robotics/microduck_rl) |

**A conclusão foi corrigida de "mecânica copiável, eletrônica é um muro rígido" para "o robô completo pode ser replicado"**:
o controlador é um módulo comercial, e a função e o protocolo das placas próprias foram totalmente reconstruídos a partir do código-fonte.
Veja detalhes em [docs/硬件方案逆向.md](../docs/硬件方案逆向.md).

## Três armadilhas em que você vai cair

1. **O Armbian roda por padrão um console de login na UART2.** O `serial-getty@ttyS2` ocupa a porta serial
   e precisa ser desativado com `systemctl mask`. A Pollen descobriu isso com `fuser -v /dev/ttyS2`.
2. **O i2c3 disputa pinos com o FUSB302.** Usar o I²C de hardware nos pinos 3/5 do conector tem o custo de **perder a negociação USB-C PD**
   (a carga comum de 5V continua funcionando).
3. **A NPU sai de fábrica desligada.** O Armbian a desativa por padrão; para rodar modelos RKNN é preciso gravar o overlay e reiniciar.

## Reprodução

```bash
# 1. 为下列装配图生成脚本拉取上游（训练工程已在 software/training/，无需此步骤）
bash scripts/fetch_upstream.sh

# 2. 重新生成装配图
python scripts/render_assembly.py upstream/microduck_rl assembly-drawings

# 3. 导出上游装配分析预览（不作为实物打印件）
python scripts/export_assembly_stl.py upstream/microduck_rl analysis-output/cad-upstream

# 4. 重新扫描孔特征
python scripts/analyze_holes.py upstream/microduck_rl/src/mjlab_microduck/robot/microduck/assets
```

Dependências: `mujoco` `numpy` `pillow` `scipy`. A renderização precisa de um contexto OpenGL disponível.
